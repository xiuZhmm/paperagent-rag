# 本次增强说明

本次直接修改既有 PaperAgent 的召回入口，并增加可独立运行、无需 API Key 的本地检索实验室。原始来源和重建说明保留在 PROJECT_PROVENANCE.md；原 README 保留为 README.original.md。新增代码由本次助手协作实现，不能把尚未理解的代码描述成个人独立研发。

## 已实现

- 自实现正IDF BM25、英文词/数字及中文单字和双字切分。
- MiniLM ONNX CPU编码，归一化向量内积排序。
- 加权RRF融合，候选池各100，保留两路名次与原始分数；零关键词匹配不进入词法候选。
- 按文档来源过滤后再排名，避免先取Top-K再过滤导致遗漏。
- PDF物理页码、文本块ID、文件摘要追踪；TXT/Markdown支持；重复文件去重。
- JSON和NumPy索引持久化；加载不执行pickle；上传名称不作为写入路径。
- 文本、模型名称、查询/文档模式组成向量缓存键。更换同名模型文件或分词配置时必须清空向量缓存。
- 原Streamlit应用可选dense/bm25/hybrid，原重排和生成接口保留；关闭重排时无需加载CrossEncoder。
- 修正Embedding API返回乱序造成的文档/向量错位，重复或缺失index直接报错。
- 修复原界面相同上传文件每次交互都重置建库状态的问题。

## 实验设计

使用BEIR公开SciFact：5,183篇标题及摘要、官方300条测试查询。开发侧排除2条与测试文本重复的查询，固定种子42抽取200条开发查询。

在开发集比较向量权重0.25、0.5、0.75，按照nDCG@10选择0.5。RRF常数固定60。分数计算为两路 `weight / (60 + rank)` 之和，不把两路原始分数直接相加。之后保持配置不变评测测试集。

| 方法 | Recall@20 | nDCG@10 |
|---|---:|---:|
| 自实现BM25 | 0.8259 | 0.6645 |
| MiniLM向量 | 0.8280 | 0.6239 |
| 加权RRF混合 | 0.8836 | 0.6793 |

相对本实验向量基线，Recall@20增加5.56个百分点，nDCG@10增加0.0554。相对BM25，nDCG@10增加约0.0149，收益更小。

混合方案有92条查询改善、168条持平、40条退化。逐题排名见reports/scifact中的JSONL，改善和退化实例见cases.md。原始分数、参数、文件SHA256、环境和查询配对bootstrap区间均已记录。

## 不能声称的内容

- 没有评测生成答案准确率、引用蕴含正确率或端到端幻觉率。
- 没有微调模型、训练Agent，也没有测CrossEncoder收益。
- 英文摘要实验不能替代中文PDF评测。内置MiniLM适合英文；中文语义检索应换模型并重新评测。
- 本次镜像模型分词器截断为128 token，BM25使用完整文本。这是当前配置下的结果，不是MiniLM能力上限，也不是官方BEIR榜单复现。
- 向量检索为NumPy全量矩阵扫描，适合小型知识库；原FAISS基线保留用于比较，不声称已实现大规模ANN服务。
- 保存知识库为本机单用户设计，没有多租户隔离、并发写入事务和生产权限系统。
- 原付费LLM生成接口未使用真实API Key运行；检索实验室、真实本地编码器和集成测试已运行。

## 可用于简历的表述

在既有PaperAgent基础上实现BM25与MiniLM向量召回的加权RRF融合，加入来源过滤、页码追踪和索引持久化；在BEIR SciFact的5,183篇文献、300条测试查询上完成独立开发集选参，Recall@20由82.80%提升至88.36%，nDCG@10由0.6239提升至0.6793，并记录逐题排名与退化案例。

投递前应自己跑通并讲清楚参数选择、两路分数差异、数据泄漏处理和至少一个退化案例。原始项目的课程/开源/助手协作来源应如实说明。

## 面试时必须能回答

1. 为什么RRF使用排名而不直接相加分数？两路分值尺度不同，且都不是可靠的正确概率。
2. 为什么保留BM25？这组科学文本存在专有名词、缩写、数字等词法线索；实测BM25本身已强于当前向量配置。
3. 为什么不能说混合永远更好？40条测试查询退化；高权重词法匹配可能挤走语义相关文献。这是待进一步验证的误差解释。
4. 你如何防止测试集调参？先按查询文本排重，再用开发集选固定参数，保存selection.json后才跑测试。
5. 下一步该改什么？先做中文领域的人工核验小评测集，再比较多语言编码器与重排。已有英文测试结果不再用于选新参数。
